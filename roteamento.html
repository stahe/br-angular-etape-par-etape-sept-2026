    4. Roteamento

    4.1. Exemplo 17: o roteador

    Uma aplicação [Angular] é uma aplicação de página única: o navegador carrega apenas uma página HTML. No entanto, a aplicação [RdvMedecins] tem várias páginas (/login, /schedule, /doctors...), cada uma com sua própria URL, que pode ser adicionada aos favoritos ou recarregada. Este é o papel do roteador do Angular: ele associa cada URL a um componente — a “página” — e exibe esse componente quando a URL muda, sem fazer nenhuma requisição ao servidor.

    // =========================================================================
// 17-router/src/app/app.routes.ts - as ROTAS da aplicação
// -------------------------------------------------------------------------
// Uma aplicação Angular é uma aplicação de página única (SPA: Single
// Page Application): o navegador carrega apenas UMA página HTML. Quando um
// link interno é clicado, nenhuma requisição é enviada ao servidor: o
// roteador muda o endereço exibido pelo navegador e substitui o
// componente exibido em <router-outlet>.
//
// Uma rota associa um CAMINHO a um COMPONENTE (uma "página"):
//   'doctors/:id'    :id é um parâmetro (/doctors/2 -> id = "2");
//   '**'             qualquer caminho: a página "não encontrado". As
//                    rotas são testadas em ordem: ela vem por ÚLTIMO.
// title: o título da aba do navegador quando a página é exibida.
// =========================================================================

import { Routes } from '@angular/router';
import { Home } from './pages/home';
import { DoctorList } from './pages/doctor-list';
import { DoctorDetail } from './pages/doctor-detail';
import { Search } from './pages/search';
import { NotFoundPage } from './pages/not-found-page';

export const routes: Routes = [
  { path: '', component: Home, title: 'Home' },
  { path: 'doctors', component: DoctorList, title: 'Doctors' },
  { path: 'doctors/:id', component: DoctorDetail, title: 'A doctor' },
  { path: 'search', component: Search, title: 'Search' },
  // Carregamento TARDIO (lazy loading): o código desta página só é baixado na
  // primeira visita (o compilador o transforma em um arquivo separado)
  { path: 'about', loadComponent: () => import('./pages/about'), title: 'About' },
  // um redirecionamento: o endereço antigo leva ao novo
  { path: 'physicians', redirectTo: 'doctors' },
  { path: '**', component: NotFoundPage, title: 'Page not found' },
];
    • linha 24: as rotas formam um array de objetos do tipo [Routes];
    • linha 25: o caminho vazio: a página inicial, no endereço /. Nunca se coloca uma / no início de um caminho;
    • linha 27: [:id] é um parâmetro: /doctors/1, /doctors/2... todos exibem o componente [DoctorDetail], que recebe o valor de [id];
    • linha 31: [loadComponent] substitui [component]: o componente só é carregado na primeira visita à página. O compilador armazena seu código em um arquivo separado, que é baixado nesse momento; isso acelera o tempo de carregamento da aplicação. Faremos isso para todas as páginas do estudo de caso;
    • linha 33: um redirecionamento: /physicians leva a /doctors;
    • linha 34: [**]: qualquer caminho. Como os caminhos são testados em ordem, este só é usado se nenhum dos outros servir: é a página “página não encontrada”;
    • [title]: o título da aba do navegador quando a página é exibida.

    // =========================================================================
// 17-router/src/app/app.ts - o "shell" da aplicação
// -------------------------------------------------------------------------
//   - routerLink="...": um link interno. Em uma tag <a>, produz um
//     href de verdade, mas um clique não recarrega a página: o roteador
//     age. routerLinkActive="active" define a classe "active" (a do
//     Bootstrap) no link da página exibida;
//   - <router-outlet />: o lugar onde o componente da
//     rota atual é exibido.
// =========================================================================

import { Component, inject } from '@angular/core';
import { toSignal } from '@angular/core/rxjs-interop';
import { NavigationEnd, Router, RouterLink, RouterLinkActive, RouterOutlet } from '@angular/router';
import { filter, map } from 'rxjs';

@Component({
  selector: 'app-root',
  imports: [RouterLink, RouterLinkActive, RouterOutlet],
  templateUrl: './app.html',
})
export class App {
  private readonly router = inject(Router);

  // o endereço atual, como um signal: router.events é um fluxo
  // (Observable, veja o exemplo 19) de eventos de navegação; guardamos o
  // fim de cada navegação, e toSignal o transforma em um signal
  protected readonly address = toSignal(
    this.router.events.pipe(
      filter((e) => e instanceof NavigationEnd),
      // decodeURIComponent: %20 volta a ser um espaço
      map((e) => decodeURIComponent(e.urlAfterRedirects)),
    ),
    { initialValue: '' },
  );
}
    • linha 19: as diretivas do roteador usadas pelo template;
    • linhas 28–35: a URL atual, exibida abaixo dos links. [router.events] é um observable (um fluxo de eventos, como mostra o Exemplo 19) que sinaliza cada etapa da navegação. Mantemos apenas os finais de navegação (linha 30), extraímos deles o endereço — incluindo eventuais redirecionamentos (linha 32) — e [toSignal] transforma o fluxo em um signal utilizável no template.

    • Linha 5: [routerLink]: um link interno. Para uma tag [<a>], ele gera um atributo [href] válido (o link pode ser aberto em uma nova aba), mas clicar nele não recarrega a página: é o roteador que altera o endereço e a exibição. [routerLinkActive="active"] aplica a classe [active] (derivada do [Bootstrap]) ao link da página exibida. Sem a opção [exact], o link / estaria ativo em todas as páginas, já que todos os endereços começam com /;
    • linhas 9–10: [[queryParams]]: os parâmetros colocados depois do [?] na URL (/search?q=general practitioner). A opção [queryParams: 'ignored'] mantém o link ativo independentemente da busca;
    • linhas 12–13: um link para o redirecionamento e um link para um endereço que não existe;
    • linha 17: [<router-outlet />]: o local onde o componente da rota atual é exibido.

    // =========================================================================
// 17-router/src/app/pages/doctor-detail.ts - uma página com um parâmetro
// -------------------------------------------------------------------------
// O parâmetro :id chega como um INPUT (graças a withComponentInputBinding,
// veja app.config.ts), como string: basta declarar um
// input com o mesmo nome. O componente deixa então de depender do
// roteador: ele também poderia ser usado como <app-doctor-detail id="2">.
// Router.navigate(...): navegar POR CÓDIGO; Location.back(): voltar
// à página anterior, como o botão Voltar do navegador.
// =========================================================================

import { Component, computed, inject, input } from '@angular/core';
import { Location } from '@angular/common';
import { Router } from '@angular/router';
import { DOCTORS } from '../data';

@Component({
  selector: 'app-doctor-detail',
  template: `
    @if (doctor(); as m) {
      <h2 class="h5">{{ m.title }} {{ m.firstName }} {{ m.lastName }}</h2>
      <p>Specialty: {{ m.specialty }}</p>
      <div class="d-flex gap-2">
        <button class="btn btn-sm btn-outline-secondary" (click)="back()">Back</button>
        <button class="btn btn-sm btn-outline-primary" (click)="next()">Next doctor</button>
      </div>
    } @else {
      <p class="text-danger mb-0">Doctor no. {{ id() }} does not exist.</p>
    }
  `,
})
export class DoctorDetail {
  readonly id = input.required<string>();
  private readonly router = inject(Router);
  private readonly location = inject(Location);

  // computed: ao ir de /doctors/1 para /doctors/2, o Angular REAPROVEITA
  // o mesmo componente e só muda o input id - o computed acompanha
  protected readonly doctor = computed(() => DOCTORS.find((m) => m.id === Number(this.id())) ?? null);

  protected back(): void {
    this.location.back();
  }

  protected next(): void {
    const id = (Number(this.id()) % DOCTORS.length) + 1;
    this.router.navigate(['/doctors', id]);
  }
}
    • linha 33: o parâmetro de rota [:id] é passado à entrada de mesmo nome. Como tudo o que vem de um endereço, é uma string;
    • linha 39: o médico exibido é calculado a partir da entrada. Ao passar de /doctors/1 para /doctors/2, o [Angular] não recria o componente: ele apenas altera o valor da entrada, e [computed] acompanha;
    • linhas 27–29: um identificador desconhecido (/doctors/9) é sinalizado;
    • linha 42: [Location.back()]: volta à página anterior, como o botão Voltar do navegador;
    • linha 47: [Router.navigate]: navegação disparada pelo código, com o mesmo array de [[routerLink]].

    // =========================================================================
// 17-router/src/app/pages/search.ts - uma página controlada pela URL
// -------------------------------------------------------------------------
// /search?q=pediatrician: como no formulário GET do curso de NestJS, a
// página é inteiramente descrita pelo seu endereço: pode ser salva nos favoritos,
// recarregada, revisitada com o botão Voltar. O parâmetro q também chega
// como um input do componente.
// =========================================================================

import { Component, computed, inject, input, linkedSignal } from '@angular/core';
import { FormsModule } from '@angular/forms';
import { Router } from '@angular/router';
import { DOCTORS } from '../data';

@Component({
  selector: 'app-search',
  imports: [FormsModule],
  template: `
    <form class="d-flex gap-2 mb-3" (ngSubmit)="search()">
      <input name="input" class="form-control" placeholder="name or specialty" [(ngModel)]="input">
      <button class="btn btn-primary">Search</button>
    </form>
    <ul class="mb-0">
      @for (m of results(); track m.id) {
        <li>{{ m.firstName }} {{ m.lastName }} ({{ m.specialty }})</li>
      } @empty {
        <li class="text-muted">No result.</li>
      }
    </ul>
  `,
})
export class Search {
  readonly q = input<string>(); // ?q=... (undefined se ausente)
  private readonly router = inject(Router);

  // o campo começa com o valor da URL e a acompanha se ela mudar
  // (botão Voltar), continuando editável: um linkedSignal
  protected readonly input = linkedSignal(() => this.q() ?? '');

  protected readonly results = computed(() => {
    const q = (this.q() ?? '').toLowerCase();
    return DOCTORS.filter((m) => `${m.firstName} ${m.lastName} ${m.specialty}`.toLowerCase().includes(q));
  });

  protected search(): void {
    // alteramos a URL; a exibição acompanha a URL (input q)
    this.router.navigate(['/search'], { queryParams: { q: this.input() } });
  }
}

    Esta página é totalmente descrita por seu endereço, assim como a de um formulário GET: você pode adicioná-la aos favoritos, recarregá-la ou voltar a ela com o botão Voltar.

    • Linha 33: o parâmetro [q] do endereço também é passado como entrada; se estiver ausente, seu valor é [undefined];
    • linha 38: o campo de entrada é um [linkedSignal]: ele assume o valor do endereço, é atualizado quando o endereço muda (com o botão Voltar), mas continua editável pelo usuário;
    • linhas 40–43: os resultados dependem do endereço, e não do campo de entrada: eles só mudam quando o formulário é enviado;
    • linha 47: o envio do formulário altera o endereço, o que altera a entrada [q], o que altera os resultados.

    O link quebrado leva a um erro de "página não encontrada":

    Você pode verificar na aba Network das ferramentas do desenvolvedor do navegador que nenhuma página é solicitada ao servidor quando você clica, exceto na primeira visita à página “About” (um arquivo chamado [chunk-XXXX.js]).     4.2. Exemplo 18: guards de navegação e páginas

    Certas páginas da aplicação [RdvMedecins] são restritas: a agenda exige login, e o gerenciamento de médicos exige o papel ADMIN. No lado do servidor, o curso de [NestJS] usou controles de acesso ([JwtAuthGuard], [RolesGuard]). O roteador do [Angular] tem os seus próprios: funções chamadas antes de exibir uma rota, que podem permitir a navegação ou redirecioná-la para outro endereço.

    Este exemplo simula a conexão sem servidor: três contas estão fixas no código.

// 18-guards/src/app/session.service.ts - uma sessão SIMULADA (sem servidor)
// -------------------------------------------------------------------------
// O usuário logado, em um serviço raiz: todos os componentes e
// todos os guards que o injetam compartilham o mesmo. (O exemplo 23 fará a
// mesma coisa com um servidor real.)
// =========================================================================

import { Injectable, signal } from '@angular/core';

export type Role = 'ADMIN' | 'DOCTOR' | 'USER';

export interface User {
  login: string;
  role: Role;
}

// três contas "fixas no código" (senha = login)
const ACCOUNTS: Record<string, Role> = { admin: 'ADMIN', pelissier: 'DOCTOR', martin: 'USER' };

@Injectable({ providedIn: 'root' })
export class SessionService {
  private readonly _user = signal<User | null>(null);
  readonly user = this._user.asReadonly();

  logIn(login: string, password: string): boolean {
    const role = Object.hasOwn(ACCOUNTS, login) ? ACCOUNTS[login] : undefined;
    if (role === undefined || password !== login) {
      return false;
    }
    this._user.set({ login, role });
    return true;
  }

  logOut(): void {
    this._user.set(null);
  }
}
    • Linha 11: os três papéis da aplicação [RdvMedecins];
    • linha 19: três contas, cada uma com uma senha igual ao nome de usuário;
    • linhas 23–24: o usuário conectado ([null] se não houver nenhum), em um signal que somente o serviço pode modificar. Como há apenas um serviço, os componentes e os guards que o injetam enxergam todos o mesmo usuário;
    • linha 27: [Object.hasOwn]: apenas as chaves próprias do objeto [ACCOUNTS] são mantidas. Sem essa precaução, o login “constructor” encontraria uma propriedade herdada por todos os objetos [JavaScript];
    • Linhas 26–33: o login é bem-sucedido se a conta existir e a senha estiver correta.

    // =========================================================================
// 18-guards/src/app/guards.ts - GUARDS de navegação
// -------------------------------------------------------------------------
// Um guard (CanActivateFn) é uma função que o roteador chama ANTES de
// exibir uma rota que o declara (canActivate: [...]). Ele retorna:
//   - true      : a navegação continua;
//   - uma UrlTree (um endereço, construído por router.createUrlTree): a
//     navegação é substituída por um redirecionamento a este endereço.
// Um guard pode injetar serviços (inject): ele roda no
// contexto de injeção da aplicação.
//
// É o equivalente, no lado do cliente, dos guards do NestJS (JwtAuthGuard,
// RolesGuard) - com uma diferença FUNDAMENTAL: um guard do cliente é
// apenas uma comodidade. O código do cliente está nas mãos do usuário, que
// pode modificá-lo à vontade. A proteção real dos dados continua sendo a
// do SERVIDOR (veja o capítulo sobre a caixa-preta).
// =========================================================================

import { inject } from '@angular/core';
import { CanActivateFn, Router } from '@angular/router';
import { Role, SessionService } from './session.service';

// a página exige estar logado
export const loginRequired: CanActivateFn = (_route, state) => {
  if (inject(SessionService).user() !== null) {
    return true;
  }
  // não logado: para a página de login, lembrando para onde queríamos ir
  return inject(Router).createUrlTree(['/login'], { queryParams: { redirect: state.url } });
};

// a página exige um dos papéis listados nos dados da rota (data.roles)
export const roleRequired: CanActivateFn = (route, state) => {
  const roles = route.data['roles'] as Role[];
  const user = inject(SessionService).user();
  if (user !== null && roles.includes(user.role)) {
    return true;
  }
  // logado, mas sem o papel adequado: de volta à página inicial, com um motivo
  return inject(Router).createUrlTree(['/'], { queryParams: { denied: state.url } });
};
    • linha 24: um guard é uma função do tipo [CanActivateFn]. O roteador lhe passa a rota a ativar e o estado da navegação (que contém o endereço solicitado, [state.url]);
    • linha 25: um guard pode injetar serviços, usando [inject], como um componente;
    • linha 26: [true]: a navegação continua;
    • linha 29: caso contrário, o guard retorna outro endereço, gerado por [createUrlTree]: a navegação é substituída por um redirecionamento para a página de login. O parâmetro [redirect] guarda a página solicitada, para voltar a ela após o login;
    • linha 34: [route.data]: os dados livres declarados pela rota (aqui, os papéis autorizados). O mesmo guard é, assim, usado para todas as páginas restritas, qualquer que seja o papel exigido;
    • linha 40: um usuário conectado cujo papel não é adequado é redirecionado para a página inicial, junto com o motivo da negação.

    Os comentários das linhas 12–16 são essenciais: um guard no lado do cliente é apenas uma comodidade para o usuário, que evita abrir uma página que talvez não funcione. O código do lado do cliente é executado no navegador; o usuário pode lê-lo e modificá-lo. A proteção dos dados continua sendo responsabilidade do servidor, que verifica as permissões a cada requisição.

    // =========================================================================
// 18-guards/src/app/pages/login.ts
// -------------------------------------------------------------------------
// Depois de fazer login, o usuário é enviado de volta à página que queria
// abrir (parâmetro ?redirect=... definido pelo guard), ou à página inicial.
// router.navigateByUrl: navegar para um endereço completo (/schedule?x=1).
// =========================================================================

import { Component, inject, input, signal } from '@angular/core';
import { FormsModule } from '@angular/forms';
import { Router } from '@angular/router';
import { SessionService } from '../session.service';

@Component({
  selector: 'app-login',
  imports: [FormsModule],
  template: `
    @if (redirect()) {
      <p class="alert alert-warning">Log in to open {{ redirect() }}.</p>
    }
    <form class="d-flex flex-wrap gap-2" (ngSubmit)="submit()">
      <input name="login" class="form-control w-auto" placeholder="login" autocomplete="username" [(ngModel)]="login">
      <input name="password" type="password" class="form-control w-auto" placeholder="password"
             autocomplete="current-password" [(ngModel)]="password">
      <button class="btn btn-primary">Log in</button>
    </form>
    @if (error()) {
      <p class="text-danger mt-2 mb-0">Incorrect login or password.</p>
    }
  `,
})
export class Login {
  readonly redirect = input<string>();
  private readonly session = inject(SessionService);
  private readonly router = inject(Router);
  protected readonly login = signal('');
  protected readonly password = signal('');
  protected readonly error = signal(false);

  protected submit(): void {
    this.error.set(!this.session.logIn(this.login().trim(), this.password()));
    if (!this.error()) {
      const redirect = this.redirect();
      // aceitamos apenas um caminho INTERNO: ele começa com /, mas não com //
      // (//site.com/... designa OUTRO site) - nenhum redirecionamento para outro site
      const internal = redirect !== undefined && redirect.startsWith('/') && !redirect.startsWith('//');
      this.router.navigateByUrl(internal ? redirect : '/');
    }
  }
}
    • Linha 33: o parâmetro [redirect], colocado no endereço pelo guard, é recebido;
    • linhas 18–20: ele é exibido ao usuário;
    • linha 41: a conexão;
    • linhas 43–47: em caso de sucesso, o usuário é redirecionado para a página solicitada ([navigateByUrl] aceita uma URL completa, incluindo parâmetros) ou para a página inicial. O parâmetro [redirect] vem da URL: qualquer pessoa pode criar um link para /login?redirect=//malicious-site.com. A linha 46 aceita, portanto, apenas um caminho interno à aplicação.
